# Резервное копирование и восстановление

## Сделать и проверить копию

Откройте PowerShell 7 в корне проекта. Пример хранит архив на локальном NTFS. Сделайте отдельную копию проверенного архива в утверждённом хранилище с шифрованием и ограниченным доступом.

```powershell
$archive = Join-Path $PWD "data/backups/ctm-$(Get-Date -Format 'yyyyMMdd-HHmmss').zip"
Push-Location backend
..\.venv\Scripts\python.exe -m app.backup create $archive
..\.venv\Scripts\python.exe -m app.backup verify $archive
Pop-Location
```

Команды завершаются ненулевым кодом при ошибке. Существующий архив защищён от перезаписи. Архив публикуется только после записи всех файлов и сверки их хешей; путь создания должен поддерживать hard link (локальный NTFS). После этого ZIP переносится обычным копированием. Планируйте место под временную копию SQLite и архив.

Команду можно выполнить на работающем приложении. Штатный SQLite Backup API включает подтверждённые изменения из WAL. Программа добавляет ровно те оригиналы FIT, которые зарегистрированы в снимке, и сверяет размер и SHA-256 каждого файла. Ошибка чтения или контрольной суммы прерывает создание. Храните архив по утверждённому сроку, проверяйте новую копию сразу после создания и регулярно проверяйте восстановление. [SQLite Online Backup API](https://sqlite.org/backup.html)

Архив содержит базу, оригиналы FIT и список разрешённых сервисных параметров. Он содержит персональные данные, GPS, хеши паролей CTM и журнал действий. `.env`, ключи Fernet, токены TLS/Tunnel и пароли OnelapFit в него не включаются. Активные сессии CTM исключаются из снимка, ожидающие ссылки отзываются, зашифрованные сессии OnelapFit исключаются, незавершённые попытки синхронизации помечаются отменёнными. Действующая база при этом не меняется. Храните действующие ключи и секреты в отдельном хранилище секретов.

## Провести восстановление

1. Выберите проверенный архив и **новый** каталог внутри существующего родителя. Обычная процедура ничего не перезаписывает.

   ```powershell
   $restored = Join-Path $PWD 'data/restore-check'
   Push-Location backend
   ..\.venv\Scripts\python.exe -m app.backup restore $archive $restored
   Pop-Location
   ```

2. В отдельной копии проекта или PowerShell-сессии укажите `CTM_DATABASE_PATH` и `CTM_FIT_PATH` для восстановленных `team.sqlite3` и `fit`. Сверьте `settings.json` и перенесите необходимые разрешённые поля в конфигурацию. Для пробного запуска оставьте `CTM_ONELAP_GATEWAY` пустым и `CTM_ONELAP_KEYS=[]`. Не запускайте пробное восстановление с действующим каталогом FIT.
3. Примените миграции из текущей версии, выполните `migrate.ps1 -Check` и запустите приложение на отдельном порте с отдельным каталогом состояния `-RunDirectory data/restore-run`. Для входа по HTTP на самом ноутбуке задайте точно соответствующий localhost-origin и тестовое значение `CTM_SECURE_COOKIES=false`. Для реального доступа восстановите HTTPS и Secure-cookie.
4. Войдите как тренер и как спортсмен. Сверьте последние дневники, FIT, RPE, аналитику и журнал. Убедитесь, что прежние сессии закрыты. После переключения сервиса выдайте заново нужные ссылки приглашения и сброса. При наличии разрешённого шлюза спортсмены подключают свои аккаунты повторно.
5. Для переключения рабочего окружения остановите прежний сервер, сделайте его последнюю отдельную копию, измените пути на проверенный восстановленный набор и запустите сервер. Оставьте прежний набор данных отдельно до сдачи проверки. При сбое публикации восстановленного каталога разберите причину и повторите с новым именем.

Контрольные суммы выявляют неполные и повреждённые архивы. Используйте только копии из доверенного хранилища.
