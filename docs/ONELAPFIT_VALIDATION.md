## Разрешённый шлюз и настройки

Шлюз — контракт **Cycling Team Monitor**, отдельный от API OnelapFit. Администратор задаёт точный HTTPS-origin шлюза только после подтверждения у провайдера разрешённого способа доступа. Реализация шлюза на стороне провайдера требуется отдельно. Клиент CTM проверяет TLS, следует только фиксированным маршрутам на выбранном origin, отклоняет перенаправления и ограничивает размеры ответов. Ссылки из ответов шлюза не используются.

| Метод шлюза | Контракт |
| --- | --- |
| `POST /v1/session` | JSON с `login` и `password`. Возвращает устойчивый `subject`, `access_token` и необязательный `refresh_token`. |
| `GET /v1/session`, `DELETE /v1/session` | Проверка и отзыв сессии с bearer-токеном CTM-шлюза. Для успеха достаточно статуса 204. |
| `POST /v1/session/refresh` | С `refresh_token` возвращает ту же схему сессии. `subject` сохраняет прежнее значение. |
| `POST /v1/rides` | С bearer-токеном принимает UTC-время `through` в секундах Unix и одно из полей `started_from` для первой загрузки или `changed_from` для инкрементальной. Границы включительные. Необязательный `cursor` продолжает тот же снимок выдачи. Ответ — `workouts` из объектов `id`, `revision`, `started_at` и необязательный следующий `cursor`. `id` стабилен в пределах аккаунта, `revision` меняется при изменении FIT, `changed_from` фильтрует по времени изменения, включая поздно появившиеся записи. Максимум 250 записей в ответе и 100 страниц за запуск. |
| `POST /v1/rides/details`, `POST /v1/rides/fit` | С bearer-токеном принимают `id`; загрузка дополнительно принимает `revision` и возвращает оригинальный FIT в двоичном теле. Метаданные соответствуют схеме элемента списка. Для временно недоступного FIT используйте 404. |

Шлюз возвращает 401 при неверных учётных данных или истёкшей сессии, 409/412/428 при интерактивном подтверждении, 429 с `Retry-After` при ограничении частоты, 5xx при временной ошибке. Сервер ограничивает частоту для всех процессов через SQLite и соблюдает паузу на 429. Остальные повторяемые ошибки дают задержку от одной минуты с экспоненциальным ростом до шести часов. Синхронизация прерывается, если шлюз после обновления токена меняет `subject`. Повреждённая версия FIT фиксируется в журнале и повторно скачивается при изменении `revision`. Если FIT временно недоступен, сервис импортирует остальные записи и повторяет выборку с прежней отметки.

1. Обновите зависимости и примените миграции до `0004_onelap` по [README](../README.md). Для пилота используйте отдельную тестовую базу и отдельный каталог FIT.
2. Получите от Magene/Onelap подтверждение транспорта, доступ к шлюзу и регион пилотного аккаунта. Проверьте, что шлюз может выдавать исходные FIT и что администратор доверяет его обработке логина и пароля.
3. Установите `CTM_ONELAP_GATEWAY` на origin шлюза, а `CTM_ONELAP_KEYS` — на JSON-массив ключей Fernet. Генерируйте ключ для каждого окружения и храните его в хранилище секретов отдельно от базы и её копий. Значения не помещайте в Git, скриншоты и журнал. Пример генерации для текущей PowerShell-сессии без вывода ключа:

   ```powershell
   $ctmOnelapKey = .\.venv\Scripts\python.exe -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
   $env:CTM_ONELAP_KEYS = ConvertTo-Json -InputObject @($ctmOnelapKey) -Compress
   Remove-Variable ctmOnelapKey
   ```

4. Оставьте `CTM_ONELAP_VALIDATED=false`. Интервал по умолчанию `CTM_ONELAP_INTERVAL_SECONDS=900`, глубина первой загрузки `CTM_ONELAP_HISTORY_DAYS=90` с возможностью выбрать 1–365 дней. `CTM_ONELAP_REQUEST_INTERVAL_SECONDS=1` задаёт минимальный интервал между запросами к шлюзу; примените лимиты согласованного транспорта. Запустите сервер с HTTPS для доступа по сети.

Пароль передаётся шлюзу при входе и не сохраняется в CTM. В БД хранится шифротекст сессии, привязанный к владельцу, поколению подключения и origin шлюза. Один аккаунт шлюза может быть закреплён за одним спортсменом. Отключение или деактивация сразу убирает локальную сессию и отменяет работу; при явном отключении сервер также пытается отозвать сессию у шлюза. Если отзыв не подтверждён, проверьте сессии через официальный сервис. Удаление из действующей базы не меняет старые резервные копии.

Для ротации остановите процессы приложения, добавьте новый ключ первым, сохранив старые, и выполните `..\.venv\Scripts\python.exe -m app.cli rotate-onelap-keys` из каталога `backend`. Команда перешифрует записи в одной транзакции. После успешной проверки можно исключить прежние ключи из рабочего окружения. Доступ к предыдущим резервным копиям требует соответствующих ключей. [Ротация MultiFernet](https://cryptography.io/en/stable/fernet/)

## Чек-лист пилота с настоящим аккаунтом

- Владелец тестового аккаунта подтверждает участие и вводит пароль сам на странице «Профиль → OnelapFit». Пароль и токены не передаются команде сопровождения. Отметьте модель, прошивку, регион и версию OnelapFit.
- Выберите глубину, в которой есть минимум две известные тренировки и одна более старая контрольная запись. Дождитесь первой выборки. Сравните список, даты и длительности с OnelapFit. Проверьте, что старый контрольный файл вне диапазона и что браузер может скачать исходный FIT с карточки.
- Запишите ещё одну поездку на устройстве, позвольте OnelapFit синхронизировать её, дождитесь следующего автоматического запуска CTM без ручного экспорта. Сверьте ID карточки на повторном запуске и загрузите тот же FIT вручную для проверки дедупликации между источниками.
- Проверьте «Проверить подключение» и ручную синхронизацию под спортсменом и тренером. Второй спортсмен не должен видеть подключение, журнал или тренировки первого. Тренер видит статусы и журнал, а подключение и отключение выполняет владелец.
- Перезапустите сервер до очередного запуска и отдельно во время синхронизации. Проверьте, что программа догружает пропущенные тренировки и резюме содержит прерванный запуск. С двумя процессами Uvicorn на одной локальной SQLite один процесс удерживает файл блокировки, второй ожидает. При выключенном сервере автоматическая загрузка приостановлена.
- На стенде шлюза проверьте истечение сессии с успешным обновлением, недействительное обновление с возвратом в профиль, 429, сетевой сбой и повреждённый FIT. Если OnelapFit запрашивает CAPTCHA или 2FA, завершите процедуру только средствами официального приложения или разрешённого шлюза. Если подтвердить доступ штатным способом нельзя, отметьте ограничение и вернитесь к ручному импорту.
- Проверьте, что после отключения пропали серверные учётные данные, повторов больше нет, ранее импортированные тренировки доступны, журнал не содержит логина, пароля, токенов или подписанных URL.
- Зафиксируйте статус каждого пункта, число импортированных тренировок, даты запусков и безопасные коды ошибок. Включите `CTM_ONELAP_VALIDATED=true` только после успешной проверки хотя бы одного настоящего аккаунта с автоматической загрузкой нескольких тренировок. До этого результат остаётся проверкой на фикстурах.
