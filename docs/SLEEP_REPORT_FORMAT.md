# Форматы отчётов для Cycling Team Monitor

Спортсмен выбирает файл `.json` или `.csv` в разделе «Сон и восстановление» → «Импорт сна и тренировок», проверяет его в предпросмотре и подтверждает загрузку. Длительность сна из отчёта попадает в аналитику, а ночные измерения видны спортсмену и тренеру в карточке дня. При конфликте импорт заменяет ручные замеры сна. Утренняя анкета и субъективные оценки сохраняются. Для показа остальных полей ранее загруженного личного отчёта тренеру спортсмен может загрузить файл повторно.

## Версия 1

Используйте JSON в UTF-8 без BOM. Файл должен содержать от 1 до 366 ночей и занимать не более 512 КиБ (524 288 байт). Ключи объектов и даты ночей должны быть уникальны. Порядок ночей в файле произвольный.

[Полный пример файла для пробной загрузки](sleep-report-v1.example.json).

| Поле | Правило |
| --- | --- |
| `schema_version` | Обязательное целое число `1`. |
| `sleep` | Обязательный массив ночей. |
| `sleep_date` | Обязательная местная дата пробуждения в формате `YYYY-MM-DD`. |
| `start_at`, `end_at` | ISO 8601 с секундами и явным смещением `±HH:MM` или `Z`. Можно передать любую из границ. Дата засыпания совпадает с `sleep_date` или предшествует ей на один день. Дата пробуждения совпадает с `sleep_date` в смещении из `end_at`. Если есть обе границы, интервал между ними составляет от 0 до 24 часов с учётом смещений. |
| `duration_minutes` | Фактическая длительность сна в целых минутах от 0 до 1440. Сервер сохраняет переданное значение. Интервал между засыпанием и пробуждением может включать бодрствование. |
| `light_minutes`, `deep_minutes`, `rem_minutes`, `awake_minutes` | Целые минуты от 0 до 1440 для лёгкого, глубокого, REM-сна и бодрствования соответственно. |
| `sleep_score` | Целое число от 0 до 100, если оценка есть у источника. |
| `avg_heart_rate_bpm` | Средний пульс за ночь в целых ударах в минуту от 1 до 300. |
| `overnight_hrv_ms` | Средняя ночная ВСР в миллисекундах, число больше 0 и до 1000. |

Неизвестные показатели опускайте или передавайте как `null`. Каждой ночи нужен хотя бы один показатель или одна граница. Нулевые минуты и оценку `0` передавайте только как фактические значения. Используйте смещение в месте измерения, даже если оно отличается от пояса профиля Cycling Team Monitor. Для UTC используйте `Z` только если `sleep_date` соответствует местной дате в этом смещении.

Минимальный отчёт содержит версию, дату и один показатель.

```json
{"schema_version":1,"sleep":[{"sleep_date":"2026-11-22","duration_minutes":450}]}
```

Используйте только перечисленные поля. Имя спортсмена, его идентификатор, почта, ключ Garmin и токены в файл не входят. Сервер связывает файл с учётной записью спортсмена по его сессии. Пульс, фазы и оценка сна сохраняются отдельно от субъективных полей утренней анкеты.

Сохранённые ночи входят в резервную копию базы Cycling Team Monitor. Пульс, ВСР и фазы видны в карточке дня. Действующая методика восстановления использует длительность и субъективную анкету.

## Повторная загрузка

Каждая ночь в файле является полным снимком за указанную дату. Для исправления сформируйте ночь со всеми её актуальными полями. После подтверждения она заменит ранее загруженную ночь за эту дату. Повтор с теми же значениями пропускается. Остальные даты сохраняются. Ошибка хотя бы в одной строке отклоняет весь файл.

## JSON версии 2

Поле `schema_version` содержит целое число `2`. Массивы `sleep` и `workouts` можно передать вместе или по одному. В файле должно быть от одной записи до 366 записей каждого типа. Лимит файла — 512 КиБ. Схема ночи совпадает с версией 1. [Готовый JSON версии 2](activity-report-v2.example.json).

Каждой велотренировке нужны `started_at` в ISO 8601 с секундами и смещением и `timer_seconds` в секундах. Начало должно быть уникальным в пределах одного файла. Дополнительные поля можно опускать или передавать как `null`.

| Поля тренировки | Единицы |
| --- | --- |
| `elapsed_seconds`, `moving_seconds` | секунды |
| `distance_m`, `ascent_m`, `descent_m`, `min_altitude_m`, `max_altitude_m` | метры |
| `avg_speed`, `max_speed` | м/с |
| `avg_power`, `max_power`, `np` | ватты |
| `avg_heart_rate`, `max_heart_rate` | уд/мин |
| `avg_cadence`, `max_cadence` | об/мин |
| `avg_temperature`, `max_temperature` | °C |
| `calories` | ккал |
| `if_value`, `tss` | исходные значения IF и TSS |

JSON и CSV передают сводку. Включайте NP, IF и TSS только если они уже рассчитаны источником. Приложение использует переданный TSS в расчётах нагрузки по действующим правилам. Зоны, графики по секундам и лучшие отрезки строятся из FIT с подходящими рядами. Загрузить FIT можно в разделе «Импорт сна и тренировок» или во вкладке «Тренировки». Приложение сопоставляет введённую ранее сводку с FIT по точному времени начала и сохраняет карточку и RPE. Если FIT уже есть, он остаётся источником тренировочных измерений. Повторный JSON или CSV с тем же временем начала обновляет сводку, пока к ней не добавлен FIT. Время начала в выгрузках для одной тренировки должно обозначать одну и ту же секунду.

## CSV Cycling Team Monitor

Сохраните файл в UTF-8 с запятыми между колонками и точкой в десятичных числах. В первой строке укажите заголовки. `kind` содержит `sleep` для ночи или `workout` для тренировки. Остальные колонки называются как поля JSON. Оставляйте пустыми показатели другого вида и отсутствующие значения. [Готовый шаблон CSV](../frontend/src/activity-report.example.csv).

Для программной проверки используется `POST /api/v1/athletes/{athlete_id}/sleep-reports/preview`. Сохранение после подтверждения отправляется через `PUT /api/v1/athletes/{athlete_id}/sleep-reports?confirm=share-and-replace`. Для CSV укажите `Content-Type: text/csv`, для JSON — `application/json`.
