# Эксплуатация на Windows

## Подготовка и запуск

Установите зависимости и примените миграции по [README](../README.md). Выполняйте команды в PowerShell 7 из корня проекта под отдельной учётной записью Windows с доступом к каталогу проекта. Ограничьте доступ к `.env`, `data`, журналам и архивам средствами NTFS. Храните SQLite и FIT на локальном диске, вне сетевой папки и каталогов синхронизации. Приложение запускается без прав администратора.

```powershell
.\scripts\server.ps1 start
.\scripts\server.ps1 status
.\scripts\server.ps1 stop
```

Сервер слушает только `127.0.0.1:8000`. `-Port` меняет локальный порт. При смене порта добавьте точный origin в `CTM_ALLOWED_ORIGINS` и укажите тот же порт прокси. `status` проверяет запущенный экземпляр и endpoint здоровья. Старт и остановка ограничены по времени; при сбое проверьте новый журнал в `data/run`. Остановка даёт приложению время завершить текущие запросы и остановить планировщик. Если ОС аварийно завершила процесс, следующий запуск освобождённой блокировки восстанавливает прерванные задачи из SQLite.

При обновлении сохраните архив, остановите сервер, обновите исходники, выполните `.\scripts\setup.ps1`, `.\scripts\migrate.ps1` и запустите сервер. При ошибке миграции оставьте приложение остановленным и проверьте резервную копию. Локальный оператор восстанавливает пароль тренера командой `..\.venv\Scripts\python.exe -m app.cli reset-coach-password --email coach@example.com` из `backend`. Она завершает существующие сессии.

При выключении или сне ноутбука CTM недоступен. После пробуждения проверьте `status`, после перезагрузки выполните `start`. Автоматический запуск после входа можно настроить в Планировщике заданий Windows под той же учётной записью. Синхронизация догружает доступные записи после запуска по сохранённому состоянию. Сроки хранения со стороны провайдера и максимальная глубина первой выборки действуют как обычно.

## Локальная сеть по HTTPS

1. Назначьте ноутбуку стабильный адрес в сети базы и выдайте участникам постоянное имя из локального DNS. Настройте входящие правила Windows Firewall для этого HTTPS-прокси только в нужных сетях. У FastAPI оставьте loopback.
2. Используйте доверенный сертификат для выбранного имени. Для закрытого стенда возможен Caddy с `tls internal`. Установите корневой сертификат CA на устройства по процедуре ИТ-команды и проверьте цепочку доверия. Закрытый ключ CA остаётся на сервере. Для реальной команды предпочтителен сертификат от доверенного CA.
3. В `.env` установите `CTM_SECURE_COOKIES=true` и `CTM_ALLOWED_ORIGINS=["https://ctm.team.example"]`, заменив имя на своё. Укажите точный HTTPS-origin без завершающего слеша. Выпускайте приглашения через выбранный адрес.
4. Запустите прокси и сервер. В следующем примере домен следует заменить на рабочий. `tls internal` нужен только для локальной CA.

```caddyfile
ctm.team.example {
    tls internal
    reverse_proxy 127.0.0.1:8000
}
```

Проверьте вход с другого устройства, корректность разрешения имени, цепочку TLS, создание приглашения и установку PWA. Доверие к заголовкам прокси ограничено loopback. Убедитесь, что прокси формирует доверенные `X-Forwarded-For` и `X-Forwarded-Proto`, не принимая произвольные значения клиента. [Caddy и HTTPS](https://caddyserver.com/docs/automatic-https) · [Caddy reverse proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)

## Удалённый доступ

Используйте управляемый HTTPS-прокси с действительным сертификатом или согласованный ИТ-командой Cloudflare Tunnel. Для Tunnel добавьте защищённое приложение Cloudflare Access с политикой участников до публикации имени. Подключите `cloudflared` на ноутбуке, маршрутизируйте только нужный hostname к `http://127.0.0.1:8000` и включите проверку токена Access на стороне Tunnel. Отдельно проверьте вход и выход CTM, срок сессии Access и передачу исходного IP у прокси. Сохраняйте одно и то же внешнее HTTPS-имя для PWA, ссылок и проверок origin. Не публикуйте Uvicorn, сетевые папки, архивы и ключи. Права спортсменов и тренеров продолжают проверяться в CTM. [Настройка Tunnel](https://developers.cloudflare.com/tunnel/get-started/) · [Публикация приложения с Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/)

В пробной установке проверьте лимит тела запроса прокси для выбранного `CTM_FIT_MAX_BYTES`, а также доступ из нужных сетей и с мобильным интернетом. Проверьте хранение сетевых журналов, чтобы они не содержали тела API-запросов, cookie и заголовок авторизации. Windows-команда отключает Uvicorn access log; журналы задач OnelapFit доступны тренерам в приложении.
